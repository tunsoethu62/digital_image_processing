# Evaluation protocol

No dataset, custom weights or measured accuracy are shipped. The JSONL example is a schema example, not an observation. Collect consented recordings covering overlapping people, jackets/bags, low light/shadows, small accessories, casual lookalikes, partial bodies and missed detections. Reserve whole connected groups for test. Select all settings on validation, then freeze them before a single final test evaluation.

## Detection

`uniform evaluate-detection` calls Ultralytics validation on cropped clothing images, validates all seven checkpoint names, and writes class precision/recall, mAP@0.5 and mAP@0.5:0.95. Classes without ground truth are reported as unrepresented; no fabricated per-class metric is supplied. The run includes available confusion matrices, PR/F1/confidence curves and validation image overlays. Inspect those artifacts and manually count false positives, wrong-class, missed boxes, localization and occlusion errors by class and challenge category. Evaluate the pretrained person detector separately on consented full-scene person boxes if person recall is a concern. Clothing metrics on person crops do not measure person detection or final decision quality.

## Person-level compliance ground truth

Use `docs/compliance_ground_truth.example.jsonl`: one full-scene frame per line, with unique `image_key` and `frame_number`. Each person needs a temporary frame-local `person_key`, original-image `box_xyxy`, one of `Compliant`, `Non-compliant`, `Uncertain`, visibility notes and human rationale. The keys are annotation references, not student identities. Record a hash of the frozen rules YAML and annotation guide. Detection labels alone cannot supply these outcomes. Reviewers judge visible garments using the same rules, without inferring hidden items or gender. A confirmed violation takes precedence over another hidden region.

Inference exports set `image_key` through `--image-key`; default is `source`. For multiple images, combine JSON records with different image keys and matching ground truth. Frame numbers are zero-based. Video timestamps use frame number / nominal source FPS; they are approximate for variable frame rate. Webcam timestamps use elapsed monotonic time. Every box is original-image pixels. No tracking/smoothing is implemented; `temporary_track_id` is null and `person_index` is local to a frame.

The evaluator greedily matches person boxes one-to-one by descending IoU >= 0.5 (configurable), never combines clothing across persons, and assigns Uncertain to unmatched ground truth people. It reports unmatched predicted people and predictions on unlabeled frames separately; these are not extra ground truth people. Audit localization mismatches before interpreting compliance scores. Inputs should contain all evaluated frames, including empty-scene ground truth, and the same exact frozen rule set. The code does not infer or verify rule-set hashes from free-text human notes; the operator must check them.

Outputs include a three-class confusion matrix (rows truth, columns predictions), macro F1 (all three classes; unsupported classes score zero), overall accuracy, uncertainty rate, coverage and accuracy among decided cases. Decided means predicted Compliant or Non-compliant; a decided guess on ground-truth Uncertain is incorrect. False-violation rate is predicted Non-compliant among **all ground-truth Compliant people**. Numerator and denominator are exported. Undefined ratios are null, not zero.

## Threshold and illumination selection

Run validation inference with `candidate_confidence` no higher than the minimum threshold you will consider (default 0.10), so cached low-confidence candidates survive. Run `uniform thresholds` to reassess cached evidence over the chosen threshold grid, optionally for one class. Inspect detection PR curves plus compliance false-violation/coverage tradeoffs; do not optimize only accuracy by avoiding decisions. The sweep cannot recover boxes removed by the candidate threshold or detector NMS. Re-run inference for changes to person detection, geometry checks, image size, preprocessing or association margin. The examples are a workflow, not optimized values.

Baseline: decoded BGR crops, YOLO's own RGB/letterbox/normalization. CLAHE: luminance-only LAB correction, clipLimit=2, 8x8 tiles, no Gaussian blur. Train two independent runs from the same pretrained initialization, split and seed: baseline and `--preprocessing clahe`. CLAHE training materializes corrected crop images into a separate dataset; inference corrects person crops identically. Validation/test images receive only the deterministic correction, no augmentation. Ultralytics training augmentation is confined to the training loader. Do not preprocess an already-corrected dataset again. Compare validation class metrics and person compliance under each matched pipeline, then choose and freeze one. Metadata prevents inference/validation from silently changing the trained preprocessing method. CLAHE is an experiment, not a default improvement claim.

## Runtime

`uniform infer` writes a `.run.json` alongside predictions with environment versions, hardware, active rules and wall-clock FPS. Model loading is excluded; decoding, two detectors, crop conversion, rules, drawing, video writing and prediction export are included. `uniform runtime` summarizes processing-only per-frame latency, aggregate processing FPS and input resolutions. For benchmark reporting record source FPS, resolution, number of people, CPU/GPU, device and warmup handling. Do not equate source playback FPS with model throughput. The UI adds rendering/download overhead. No actual real-camera benchmark has been performed here.
